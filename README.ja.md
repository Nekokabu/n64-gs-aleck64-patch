# n64-gs-aleck64-patch

[English](README.md)

**GameShark Pro v3.30**（N64）のファームウェアダンプにパッチを当て、
GameShark のメニューから **Aleck64（CIC-NUS-5101）** のゲームを起動できるようにするツールです。

対応ビルド（ヘッダ 0x30 のビルド文字列）:

| ビルド         | shell.bin の CRC32 |
|----------------|--------------------|
| `09:54 Mar 27` | `65B194D9`         |
| `15:56 Apr 4`  | `6E14E38B`         |

標準のファームウェアは、ゲームの先頭 1MB だけを RAM にコピーしてから起動します。
一方 5101 の IPL3 は（ヘッダのエントリポイントが 0x80100400 のとき）0x3FE000 バイトを
0x80000400 に読み込むため、これを前提とする Aleck64 のゲームは改造していない GameShark では起動しません。

## パッチ内容

変更するのは `shell.bin`（メニュー本体。0x80200400 にロード）だけです。

| Mar 27       | Apr 4        | 元の内容                    | パッチ後                                  |
|--------------|--------------|-----------------------------|-------------------------------------------|
| `0x802005DC` | `0x802005E4` | ゲーム起動ルーチンの先頭    | `j 0x80205C00`                            |
| `0x80205C00` | `0x80205C00` | どこからも呼ばれない PC リンク用ルーチン（82 ワード） | 新しい起動ルーチン（79 ワード、`launch.s`） |
| `0x80218410` | `0x80218A90` | ローダースタブの `lui $k0, 4` | `or $k0, $a3, $zero`（コピー量を `$a3` で受け取る） |

起動ルーチンは両ビルド共通のソースを、それぞれのビルドのアドレス（`launch.s` の先頭に記載）で
アセンブルしたものです。

新しい起動ルーチンの動作:

* ROM 0x524/0x528 のワードで 5101 の IPL3 を判別
* 実機の 5101 IPL3 と同じく、ヘッダのエントリポイントから 0x100000 を引く
  （`DE` コードがある場合はその値をそのまま使用）
* その結果が 0x80000400 なら、1MB ではなく **0x3FE000 バイト**をコピー。
  ローダースタブと F0/F1 パッチリストは RAM 最上部、スタックのすぐ下（コピー範囲の外）に置く
* それ以外のゲームは元のルーチンとまったく同じ動作

コードジェネレータ（trainer）の有効・無効どちらでも同じルーチンが使われます。

`shell.bin` はファームウェアの LZARI と完全互換の圧縮器（`lzari.c`。元の `shell.bin` を
再圧縮すると元のデータとバイト単位で一致）で再圧縮し、ファイルテーブルを作り直します。
ブートローダー、ほかのファイル、設定領域、コードリスト、0x2EF00 のデータはそのまま残ります。

ファームウェアの中身が変わるため、**キーコードはすべて変わります**。
ツールはキーコード表（Mario / Diddy / Zelda / Yoshi と、新しく追加する
「Aleck64 (CIC-5101)」）を作り直し、`--boot` で選んだキーをヘッダに書き込みます。

## ビルド

```sh
make
# または
cc -O2 -std=c99 -o gs_aleck64_patch gs_aleck64_patch.c lzari.c
```

## 使い方

```sh
./gs_aleck64_patch --rom6105 <6105のROM> [--boot <cic>] <入力ファームウェア> <出力ファームウェア>
```

* `--rom6105`（必須）: CIC-NUS-6105 の IPL3 を持つ ROM（先頭 0x1000 バイトだけ読みます）。
  「Zelda」のキーコードの計算に使います。
* `--boot`: ヘッダに書き込むキー。`6102`（既定）、`6103`、`6105`、`6106`、`5101`。
  GameShark は上に挿したカートリッジの CIC と一致するときだけ起動します。
  あとから Key Codes メニューで切り替えることもできます。
* 入力は対応ビルドの改造していない v3.30 のダンプ（256KB、`.z64` / `.n64` / `.v64`）。
  ビルドは自動で判別し、出力は入力と同じバイトオーダーで書き出します。

パッチ後のキーコード:

| キー                        | 09:54 Mar 27                       | 15:56 Apr 4                        |
|-----------------------------|------------------------------------|------------------------------------|
| Mario World 64 & Others (6102) | `271F6120 DEEA5464 78 80180000` | `1A965CD6 59FEF6D9 76 80180000` |
| Diddy, 1080, Banjo, Griffey (6103) | `0E1E863E E4168444 76 80201000` | `4257BA63 B75DC4E2 0C 80201000` |
| Zelda (6105)                | `49BAD096 6F07D047 D1 80190000` | `7CF3A93C DDC550F0 F3 80190000` |
| Yoshis, F-Zero, C'World (6106) | `1AAC5E5E 7199FF24 76 80200400` | `FE2AF47C B2DD5D51 94 80200400` |
| Aleck64 (CIC-5101)          | `6BA67BBA C5F16A96 44 80201000` | `390F92E7 4A9D25CD 7B 80201000` |

（CRC1 CRC2、チェックディジット、エントリポイント）この値はファームウェアのコード部分だけで
決まるので、同じビルドならどのダンプでも同じになります。

## 注意

* **改造したファームウェアの書き込みは GameShark を起動不能にする可能性があります。**
  元のダンプを保管し、外部のライターで書き戻せることを確認してから使ってください。
* 旧ファームウェアのキーコードはパッチ後のファームウェアでは使えません（逆も同様）。
* ローダースタブはスタックポインタの 0x300 バイト下に置きます。ゲーム起動時のメニューの
  スタック使用量が約 6KB 未満であることを前提にしています。
* CPU エミュレータ上で起動処理（コピー量、レジスタ値）を確認済みです。
  実機での動作は自己責任で確認してください。
